# План доработок: ревизия + задачи для исполнителя

Документ — результат ревизии расширения против исходного микрофронта
`~/front/env-jupyter-server` (консоль Cloud.ru ML Space). Структура: сначала находки
(что не так и где), затем фазы работ с критериями приёмки. Выполнять фазы по порядку:
Фаза 1 и 2 — исправления корректности и зависаний, 3–4 — функционал и UX, 5 — верификация.

Правила для исполнителя:

- Ссылки на веб-приложение (`src/...` с префиксом `env-jupyter-server`) — это референс
  поведения, код оттуда не копировать, только контракты.
- Сохранять существующие паттерны: чистые модули без `vscode`-импорта для логики
  (см. `docs/decisions.md` Р7), инъектируемый `fetchImpl`, типизированные `ApiError`.
- UI: **никаких новых иконок**. Действия — только текстовые пункты меню/QuickPick с
  описаниями. Существующие `icon` у команд в `package.json` убрать, кроме
  `view/title.navigation` (там VS Code требует иконку).
- Все новые строки UI — на русском, подписи статусов и действий брать из референса
  (раздел «Справочник» внизу).

## Часть A. Ревизия

### A1. Сверка ручек (extension ↔ веб-консоль)

Используемые ручки корректны и совпадают с микрофронтом:

| Ручка | Extension | Веб (референс) | Вердикт |
|---|---|---|---|
| `GET /user/v1/workspaces/` | `apiClient.ts:61` | свитчер консоли | ✔ |
| `GET /notebooks/v2/?include_private=true` | `apiClient.ts:68` | `urlUtils.ts:4` | ✔ |
| `POST /notebooks/v4/{uid}/pause` | `apiClient.ts:75` | `urlUtils.ts:24` | ✔ |
| `POST /jup_web_app/v3/notebooks/{ns}/resume_request` | `apiClient.ts:83` | `urlUtils.ts:27` | ✔ (namespace воркспейса — верно) |
| `GET /jup_web_app/v3/notebooks/config?region_type=` | `apiClient.ts:98` | `urlUtils.ts:21` | ⚠ веб всегда шлёт `region_type=MT`; extension выводит из URL ноутбука (`sshUrl.ts:32`). Работает, но проверить на не-MT регионах |
| Заголовки `Bearer` + `x-workspace-id` + `front-initiator-namespace` | `apiClient.ts:141-146` | ft-rest-client | ✔ |

Расхождения:

1. **Resume-body для harbor-образов**: веб (`useResumeNotebookMutation`) подтягивает
   `labels` датахаб-образа через `POST /ar_mgmt/v1/docker_images`; extension шлёт
   `labels: {}` (`resumeBody.ts:40`). Для стандартных образов может терять
   `mlspace.notebook.*`-лейблы — проверить и добавить lookup с fallback.
2. **Статусная модель неполная — это баг.** В консоли 20 статусов
   (`env-jupyter-server/src/types/index.ts:127-147`), в extension 13 (`api/types.ts:4-17`).
   Отсутствуют: `pulling`, `for_pause`, `for_resume`, `for_create`, `for_delete`,
   `deleted`, `rejected`. `mapConsoleNotebook` кастует строку без валидации
   (`notebookMapping.ts:41`) → неизвестный статус проваливается в default-ветку
   `presentNotebookStatus` (иконка «?», contextValue `notebook.other`, ни одного действия
   в меню). Ноутбук в статусе `pulling`/`for_resume` выглядит сломанным.
3. **Открытие в браузере**: веб открывает `{url}lab/?ws={workspaceId}` и
   `{url}tree/?ws={workspaceId}` (`useJupyterServerConnectActions.tsx:23,42`); extension
   открывает голый `url` (`commands/index.ts:174`).

### A2. Авторизация и протухание токенов — источники зависаний

Схема (браузерный mint cookie `iframe_auth_cookie`, кэш, re-mint по 401 c одним retry —
`apiClient.ts:118-124`) в целом рабочая. Конкретные дефекты:

- **[H1] Нет таймаута HTTP-запросов.** `consoleHttp.ts` не ставит `req.setTimeout` —
  зависший сокет (корпоративный прокси, обрыв сети) вешает всё навсегда: дерево крутит
  «Loading...», `pollUntil` застревает, команда не завершается.
- **[H2] Headless-mint при отсутствии сессии.** `getAccessToken` (`tokenProvider.ts:87-96`)
  не проверяет `isSignedIn` перед `mint(false)` → запуск headless Chrome на 30 секунд,
  когда пользователь вообще не логинился/уже разлогинен. `handleExpiredSession` при
  `!isSignedIn` молча выходит — итог: 30-сек зависание без какого-либо UI.
- **[H3] `pollUntil` не реагирует на протухание сессии.** `catch {}` глотает всё
  (`commands/index.ts:258-262`), включая `NotSignedInError` → до 5 минут повторных
  запусков headless Chrome (через цепочку `mint`) под неубиваемым прогрессом.
- **[H4] `pollUntil` не останавливается на терминальной ошибке.** Если resume упал и
  статус стал `error`, поллинг крутится до таймаута и молча исчезает — ни ошибки, ни
  подсказки про логи.
- **[H5] Прогрессы без отмены.** `pollUntil` (`commands/index.ts:253`), SSH-подключение
  (`sshController.ts:59`, `notebookController.ts:61`) — `withProgress` без
  `cancellable: true`. Интерактивный вход `signIn` (до 300 с, `tokenProvider.ts:143`)
  вообще без прогресса в VS Code: пользователь не понимает, что расширение ждёт браузер.
- **[H6] `NotSignedInError` в командах.** `withErrorHandling` (`commands/index.ts:279-297`)
  знает только `ApiError` → на `NotSignedInError` показывает сырой тост
  «Cloud.ru: Error...» поверх уже показанного prompt'а re-auth. Хуже: `selectWorkspace`
  ловит её и предлагает **вручную вставить workspace id** (`commands/index.ts:190-193`) —
  бессмысленный сценарий при протухшей сессии.
- **[H7] Несогласованная реакция на 401 после retry.** `withErrorHandling` на
  `ApiError.isAuth` делает тихий `auth.signOut()` без предложения перелогиниться —
  а параллельный путь `handleExpiredSession` показывает «Sign In». Должен быть один путь.
- **[H8] Дубли запросов в поллинге.** Каждая итерация `pollUntil` делает `tree.refresh()`
  (который сам дёргает `listNotebooks` в `getChildren`) **и** свой `listNotebooks` —
  2 запроса каждые 3 с. Нет и dedupe параллельных `listNotebooks` (дерево + serverProvider
  + поллинг могут одновременно провоцировать конкурирующие mint'ы).

### A3. Кеши SSH-туннелей — «зависон» после pause/resume

- **[H9] `CloudruServerProvider.forwards` живёт вечно** (`serverProvider.ts:65-67`):
  после pause→resume под пересоздан, туннель мёртв, но `ensureForward` возвращает старый
  `baseUrl` → Jupyter-ядро бесконечно «подключается». Инвалидации по смене статуса нет.
- **[H10] То же в `NotebookViewController`** (`notebookController.ts:53-54`): shim и
  соединение кешируются по uid навсегда → webview с вечным лоадером после рестарта
  ноутбука.
- **[H11] Интерактивные диалоги внутри `resolveJupyterServer`.** `resolveTarget` может
  открыть file-picker ключа и InputBox эндпоинта (`sshConfig.ts:46-64`) прямо из пикера
  ядер Jupyter — выглядит как зависание пикера.

### A4. UX-пробелы

- Welcome-вью врёт: «No workspace selected» показывается всегда при пустом дереве —
  включая случаи «воркспейс выбран, но ноутбуков нет», «список не загрузился», «сессия
  истекла» (`package.json:62-66`, welcome виден при пустом `getChildren`).
- Статусы в дереве — сырые enum'ы (`paused_by_timer` в тултипе и фильтре); в консоли —
  человеческие подписи («Остановлен по времени»).
- Дерево не обновляется само: если ноутбук запустили из веб-консоли, спиннер статуса
  «замерзает» до ручного Refresh.
- Тултип не показывает автовыключение (`pause_at` есть в типе, не выводится), аллокацию,
  режим доступа.
- Нет: удаления ноутбука, логов, генерации SSH-ключа через API (ключ просят файлом),
  создания ноутбука, статуса проекта (preflight). Всё это есть в микрофронте (см. Фазу 3).

## Часть B. План работ

### Фаза 1 — Сеть и авторизация: устранить зависания [P0]

**1.1 Таймаут в `consoleHttp.ts`** _(фиксит H1)_
- `req.setTimeout(30_000)` + `req.destroy(new Error(...))` по таймауту; reject маппить в
  `ApiError("network", ...)` c понятным текстом «Cloud.ru API не отвечает (таймаут 30 с)».
- Таймаут — параметр `HttpFetch` c дефолтом, чтобы тесты могли его сжать.
- Приёмка: юнит-тест с сервером, который не отвечает, — промис отклоняется за ~таймаут.

**1.2 `getAccessToken`: short-circuit без сессии** _(H2)_
- В начале `getAccessToken` (`tokenProvider.ts:87`): если `!await isSignedIn()` — сразу
  `throw new NotSignedInError()` без запуска браузера.
- Интерактивный `signIn()` — единственный путь, запускающий браузер при разлогине.
- Приёмка: при разлогиненном состоянии ни один вызов API не запускает Chrome (проверить
  логом), команды мгновенно получают `NotSignedInError`.

**1.3 Единый путь обработки auth-ошибок в командах** _(H6, H7)_
- `withErrorHandling`: добавить ветку `err instanceof NotSignedInError` → выйти тихо
  (prompt уже показал `promptReauth`).
- Ветку `ApiError.isAuth` заменить с тихого `signOut()` на вызов общего
  `auth.handleExpiredSession()` (сделать метод публичным или добавить публичную обёртку) —
  чтобы всегда был тост «Cloud.ru session expired» + кнопка «Sign In».
- `selectWorkspace` (`commands/index.ts:183-194`): `NotSignedInError` — rethrow (не
  предлагать ручной ввод id); ручной ввод оставить только для реальных сетевых ошибок.
- Приёмка: при протухшей SSO-сессии любая команда даёт ровно один тост с «Sign In»,
  без сырых «Cloud.ru: Error...», без InputBox с workspace id.

**1.4 Переработать `pollUntil`** _(H3, H4, H5, H8)_
- `withProgress(..., cancellable: true)` — отмена прекращает поллинг (операция на сервере
  уже запущена; так и написать в тексте прогресса).
- Один `listNotebooks` на итерацию: полученные данные отдавать дереву напрямую — добавить
  в `NotebooksTreeProvider` метод `applyNotebooks(list)` (обновляет `lastNotebooks` и
  эмитит событие) вместо слепого `refresh()`; `getChildren` при наличии свежих данных не
  должен рефетчить (см. 1.6).
- Ошибки: `NotSignedInError` → прервать поллинг молча; прочие ошибки — терпеть максимум
  N=5 подряд, затем прервать с тостом.
- Терминальные статусы: для resume — прерваться, если статус стал `error`/`rejected`
  (тост «Не удалось запустить {name}» + кнопка «Показать логи» после Фазы 3.2); для pause —
  аналогично на `error`. По таймауту — warning-тост, а не молчание.
- Приёмка: юнит-тесты на извлечённую чистую функцию цикла (успех, отмена, error-статус,
  NotSignedInError, серия сетевых ошибок).

**1.5 Прогресс интерактивного входа** _(H5)_
- `cloudru.signIn`: обернуть в `withProgress` (Notification, cancellable) с текстом
  «Завершите вход в окне браузера…»; отмена закрывает браузер (пробросить AbortSignal в
  `doMint`/`mint(true)` — при отмене `browser.close()`).
- При неудаче/закрытии окна: тост «Вход не выполнен» + кнопка «Повторить».
- Приёмка: отмена прогресса реально закрывает окно браузера; повторный вход работает.

**1.6 Dedupe `listNotebooks` + индикация тихого mint'а** _(H8)_
- В `ConsoleApiClient` (или тонкой обёртке): если `listNotebooks(ws)` уже в полёте для
  того же workspaceId — вернуть тот же промис.
- Пока идёт первый silent mint после перезагрузки окна, дерево должно показывать
  `view.message = "Выполняется вход в Cloud.ru…"` (снимать после первого успешного
  ответа) — сейчас это выглядит как беспричинный вечный спиннер до 30 с.
- Приёмка: лог не содержит параллельных `listNotebooks`; после reload окна в дереве
  видно сообщение о входе.

### Фаза 2 — Статусная модель и жизненный цикл туннелей [P0]

**2.1 Полный enum статусов** _(A1.2)_
- `api/types.ts`: добавить `pulling`, `for_pause`, `for_resume`, `for_create`,
  `for_delete`, `deleted`, `rejected`.
- `notebookMapping.ts`: нормализация с whitelist; неизвестный статус → логировать warn и
  маппить в специальное `unknown` (добавить в enum) вместо слепого каста.
- `presentNotebookStatus`: RU-подписи и группы как в консоли (справочник ниже);
  транзиентные (`pulling`, `for_*`, `creating`, `resuming`, `pausing`, `waiting`,
  `deleting`, `fixing`) — спиннер и `notebook.busy`; `deleted`/`rejected` —
  `notebook.other`.
- Правила меню (`package.json` when-clauses) сверить с консолью:
  pause доступна только для `running` (в консоли stop скрыт/задизейблен для
  `warning,error,deleting,for_delete,deleted,creating,for_create,rejected` —
  `types/index.ts:471-480` референса); resume — только для четырёх `paused*`.
- Добавить в `StatusPresentation` поле `label` (RU) и использовать его в description
  дерева, тултипе и фильтре по статусам (фильтр показывает «На паузе (3)» вместо
  `paused`).
- Приёмка: юнит-тесты на все 20+1 статусов (подпись, contextValue, busy/paused/running).

**2.2 Инвалидация туннелей и shim'ов** _(H9, H10)_
- В `CloudruServerProvider`: хранить рядом с forward'ом «отпечаток» ноутбука
  (например `nb.url`). В `provideJupyterServers` при обновлении списка: если ноутбук
  исчез/не running/url сменился — `connection.dispose()` и удалить forward. Плюс лёгкий
  health-probe (HTTP GET на baseUrl c коротким таймаутом) в `ensureForward` перед
  переиспользованием; мёртвый туннель — пересоздать.
- То же в `NotebookViewController.ensureShim`: перед reuse — probe; при провале —
  disposal и пересоздание. Подписаться на завершение pause (после `pollUntil`) —
  инвалидировать записи этого uid (проще: событие «notebookStateChanged(uid)» из команд).
- `signOut`/смена воркспейса: дропать все forwards/shims/panels.
- Приёмка: сценарий pause→resume→«Open in VS Code»/выбор ядра работает без перезапуска
  VS Code (ручная проверка в Extension Development Host — описать шаги в PR).

**2.3 Без диалогов в `resolveJupyterServer`** _(H11)_
- `resolveTarget` получает флаг `interactive: boolean`. Из `resolveJupyterServer` —
  `interactive: false`: если ключа/эндпоинта нет — бросить ошибку с текстом
  «SSH не настроен. Выполните команду “Cloud.ru: Настроить SSH”» (+ автоматически ключ
  из Фазы 3.3 сделает этот случай редким).
- Приёмка: выбор ядра при ненастроенном SSH мгновенно показывает ошибку, не открывая
  диалогов.

**2.4 Resume-labels для harbor-образов** _(A1.1)_
- Портировать lookup из `useResumeNotebookMutation`: `POST /ar_mgmt/v1/docker_images`
  (фильтр по name/tag; см. `dataService.ts:162-206` референса) → взять labels найденного
  образа; при любой ошибке — текущее поведение (`labels: {}`), не блокировать resume.
- Приёмка: юнит-тест на сборку тела с/без найденного образа; ручной resume стандартного
  образа.

### Фаза 3 — Функционал из env-jupyter-server [P1]

**3.1 Удаление ноутбука**
- Ручка: `DELETE /notebooks/v4/{uid}` (референс `urlUtils.ts:7`).
- Команда «Удалить…» в меню действий (доступна кроме `deleting/for_delete/deleted`).
  Подтверждение `showWarningMessage(..., { modal: true })` с текстом консоли:
  «{name} будет удален без возможности восстановления». После — poll до исчезновения из
  списка (переиспользовать `pollUntil`).
- Приёмка: удаление тестового ноутбука из дерева; отказ в модалке ничего не делает.

**3.2 Логи ноутбука**
- Ручка: `GET /notebooks/v2/{namespace}/{notebookName}/logs?region={region}` →
  `{logs, notebook_status, status_reason}` (референс `dataService.ts:153-160`).
  namespace — как в resume (workspace → fallback notebook).
- Команда «Показать логи»: открыть виртуальный документ
  (`workspace.openTextDocument({ content, language: "log" })`); в начало файла добавить
  строку `status: ..., reason: ...`. Недоступна для `paused*`/`deleting`-статусов (как в
  консоли).
- Использовать в тостах ошибок resume (кнопка «Показать логи», см. 1.4).
- Приёмка: логи running-ноутбука открываются в редакторе.

**3.3 SSH-ключ через API (убрать ручной выбор файла)**
- Ручки: `GET /user/v1/user_ssh_keys/`, `POST /user/v1/user_ssh_keys/generate`,
  `POST /user/v1/user_ssh_keys/public_key` (референс `dataService.ts:122-138`).
- Команда «Получить SSH-ключ (сгенерировать новый)»: модальное подтверждение с текстом
  консоли «При генерации нового ключа старый перестанет работать», затем `generate`,
  приватный ключ сохранить в `globalStorageUri/ssh/mlspace.private_key` с mode 0600 и
  прописать в `cloudru.ssh.privateKeyPath`; предложить «Сохранить копию…» (save dialog).
- В `ensurePrivateKey`/`ensureKeyPath` (`sshConfig.ts:98-155`): если ключ не настроен —
  QuickPick из двух текстовых пунктов: «Сгенерировать новый ключ (старый перестанет
  работать)» / «Выбрать файл ключа…» — вместо немедленного file-picker'а.
- Приёмка: на чистом профиле «Browse Files (SSH)» проходит без ручного файла (сценарий
  с генерацией); юнит-тест на выбор пути.

**3.4 Статус проекта (preflight)**
- Ручка: `GET /notebooks/v2/preflight` (референс `dataService.ts:309-315`).
- Дёргать при выборе воркспейса и перед resume: если проект приостановлен — понятная

- Приёмка: юнит-тест маппинга ответа; при активном проекте поведение не меняется.

**3.5 Открытие в браузере с `?ws=`**
- `cloudru.openNotebookInBrowser` → два пункта QuickPick: «Открыть Jupyter (tree)» /
  «Открыть JupyterLab» → `{url}tree/?ws={workspaceId}` и `{url}lab/?ws={workspaceId}`.
- Приёмка: URL содержит `ws`-параметр активного воркспейса.

**3.7 Автовыключение и детали в тултипе**

  включено), «Пауза запланирована: {pause_at}», «Аллокация: {allocation}», «Доступ:
  индивидуальный/совместный/мультидоступ».
- Bulk-переключение автостопа НЕ делать (веб-специфично).

**3.8 Создание ноутбука — минимальный путь**
- Сначала: пункт «Создать Jupyter Server в консоли…» — открыть страницу создания в
  браузере (`vscode.env.openExternal`).
- Полный QuickPick-wizard (имя → регион → PAYG/аллокация → instance_type → образ, ручки
  `/jup_web_app/v3/notebooks/config`, `/v1/allocations/by-workspace/{ws}`,
  `/ar_mgmt/v1/docker_images`, `check-existence`, `POST /jup_web_app/v3/notebooks/{ns}`) —
  отдельной фазой ПОСЛЕ приёмки всего остального; не начинать без явного запроса.

Вне скоупа (не делать): шаринг пользователей (multiuser), S3/NFS/Secret Manager,
тикеты в поддержку, модификация описания, встроенный мониторинг.

### Фаза 4 — UI/UX: текстовые действия, честные состояния [P1]

**4.1 Единый список действий с описаниями (главный паттерн)**

**4.5 Авто-обновление дерева**

## Справочник: статусы и тексты (из консоли)

| Статус | Подпись RU | Группа |
|---|---|---|
| running | Подключен | running |
| error | Ошибка | error |
| warning | Предупреждение | warning |
| paused | На паузе | paused |
| paused_by_metrics | Остановлен по нагрузке | paused |
| paused_by_schedule | Остановлен по расписанию | paused |
| paused_by_timer | Остановлен по времени | paused |
| fixing | Нет соединения | busy |
| creating | Создаётся | busy |
| waiting | Ожидает ресурсов | busy |
| pulling | Скачивание образа | busy |
| for_create / for_resume / resuming | Запускается | busy |
| for_pause / pausing | Останавливается | busy |
| for_delete / deleting | Удаляется | busy |
| deleted | Удален | other |
| rejected | Не создался | other |

Тексты (использовать дословно):
- Стоп: «Будут утеряны несохраненные данные вне NFS. Остановить {name}?»
- Удаление: «{name} будет удален без возможности восстановления.»
- Нет доступа: «Это индивидуальный Jupyter Server другого пользователя, у вас нет доступа.»
- Лимит: «Запрещено администратором воркспейса.»
- Проект неактивен: «Не хватает средств или прав для создания и подключения Jupyter Server.»
- Новый SSH-ключ: «При генерации нового или загрузке ключа из файла старый перестанет работать.»
